The preserved evaluation cohort contains 20 confirmed fresh computers, 12 allocation failures, and 25 unsuccessful outcomes. Failed rows remain in reliability.json. Success requires an exact match with the independent integer-cent oracle, a matching checkpoint after stop/resume, and confirmed deletion. A model response alone never establishes success.

The cohort includes the first end-to-end smoke run and all subsequently confirmed reconciliation computers, including intentional interruption and failed model attempts. No allocated failed row is removed. Pre-allocation refusals are kept in allocation_failures and cannot count toward twenty fresh computers. This is an engineering cohort, not a fixed-version model comparison.

Elapsed time includes boot, model calls, persistence verification, and cleanup. Cost is an estimate from configured runtime and token rates. Zero model prices can mean verified free models or unconfigured prices; each run records its free-only policy and provider-reported model cost when available. Observed failure analysis: two early generated programs required whole rupees instead of integral cents, rejecting valid values such as 12.34. Their repair attempts also produced syntax errors. The original contract and a failed program are archived under reports/evidence/. The clarified contract explicitly distinguishes 12.34 (valid) from 12.345 (invalid); later runs record its SHA-256. Earlier failures remain scored. A separate early attempt received HTTP 400 from the model provider; its original response body was unavailable, so its precise cause is not claimed. New diagnostics retain a bounded, credential-redacted provider error message.

The later free Nemotron phase had a two-call budget. Several attempts exhausted that budget without an accepted Python execution request, and a provider HTTP 502 was observed. These were not relabeled as successes. The free North model produced the seven verified outputs; the local default was restored to it. Contracts, models and call budgets changed between documented phases, so this cohort cannot establish an isolated model ranking or production readiness. Timing summaries include fast failures and the deliberate interruption.

Known limits: synthetic exports use one schema and small files. Stop/resume tests disk persistence, not full memory snapshots. SIGKILL and host power loss require manual orphan reconciliation. The pre-execution hook restricts shell entry points, but generated Python still has guest permissions. The pinned cloud SDK does not expose an outbound network policy; no network containment is claimed.
